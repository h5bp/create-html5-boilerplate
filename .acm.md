## Implementation Summary

`create-html5-boilerplate` is a Node.js ≥20 CLI scaffolding tool that:

1. Downloads a tarball of HTML5 Boilerplate from npm registry
2. Extracts to a temporary staging directory
3. Copies contents to user-specified destination
4. Optionally configures language code and jQuery removal

## 4. Explicit Non-Goals & Unhandled Failure Modes

### Unhandled Failure Modes

1. **Network Timeout After 15s**
   - No exponential backoff or circuit breaker
   - User must retry manually or check internet connectivity
   - Degradation: Fail-closed (process.exitCode = 1)

2. **npm Registry Unavailable**
   - Metadata fetch fails → propagated as "Failed to fetch release metadata"
   - No fallback to secondary registry or local cache
   - User-facing error directs to check connectivity + registry URL

3. **Malformed Tarball**
   - tar.extract({strict: true}) aborts with descriptive error
   - Partial extraction is impossible (tar library atomicity guarantee)
   - Temp directory cleaned up in finally block

4. **Destination Directory Permission Denied (EACCES, EPERM)**
   - fs.cp() fails; error categorized in describeFailure()
   - User-facing hint: "Check permissions for the destination and temporary directory"
   - No attempt to chmod or escalate privileges

5. **Disk Space Exhaustion**
   - fs.createWriteStream() would eventually error (ENOSPC not explicitly handled)
   - Falls through to generic catch block; temp cleanup still occurs
   - User-facing message: generic "Could not generate project" + reason

### Degradation Behavior

- **Fail-Closed:** All errors result in non-zero exit code (process.exitCode = 1)
- **No Partial Success:** CLI either succeeds completely or rolls back all mutations
- **No Silent Degradation:** All errors are logged with diagnostic context (error code, path, reason, hint)

### Partial Recovery & Compensating Transactions

- **No Rollback of Destination:** If fs.cp() partially succeeds before error, previous files remain
  - Mitigation: Pre-check destination is empty or user confirmed override
  - Non-Goal: Atomic rollback of destination copy (would require Shadow Directory + Atomic Rename)
- **No Retry State:** Each CLI invocation is independent; no persistent retry queue
- **Temp Directory Recovery:** Orphaned temp dirs cleaned by OS; mkdtemp suffix ensures no collisions

## Risk Factors & Accepted Trade-offs

| Factor                             | Status                  | Rationale                                                                                                         |
| ---------------------------------- | ----------------------- | ----------------------------------------------------------------------------------------------------------------- |
| **Network retry logic**            | None                    | Timeout budget is sufficient for healthy connections; retries add complexity without affecting happy path         |
| **Destination rollback**           | Not implemented         | Pre-flight check (empty or confirmed) reduces likelihood; full atomic semantics not critical for scaffolding tool |
| **Proxy authentication**           | Delegated to npm config | Respects `$npm_config_*` env vars; no additional auth layer                                                       |
| **Archive signature verification** | SSRI integrity only     | NPM registry tarball integrity is trust anchor; signature verification out of scope                               |
| **Multi-region fallback**          | Not supported           | npm CDN is single point of truth; multi-region add complexity without clear benefit                               |
